## 1. Definitions

- **rtpDenominator**: RTP = expected total payout of a game round divided by the base-game stake of that round. A round is one paid base-game spin plus every free spin it triggers, including retriggers. Free spins have no stake and are not part of the denominator.
- **units**: Internally all wins are integers in line-bet units. Multipliers ("x bet") in reports are multiples of the total bet (line bet x 20 paylines).
- **displayedWins**: Displayed wins are the credits paid to the balance. They do NOT include the stake: the stake is debited separately when the round starts. Net result of a round = win - stake.
- **hit**: A hit is a round with a payout greater than zero (any line win, scatter win or feature win).
- **netPositive**: A net-positive round pays strictly more than its stake.
- **losingRound**: A losing (no-win) round pays nothing. A net-losing round pays less than its stake.
- **capRule**: The total payout of one round is capped at limits.maxWinMultiplier x total bet. When the cap is reached the round ends immediately and remaining free spins are forfeited (they could not pay anything).

## 3. Method

Exact. Every reel-stop combination of the base and free-spin reel sets is enumerated with an independent evaluator. The free-spin feature (including retriggers and the total-spins limit) is solved as a Markov chain whose win distribution is propagated by FFT convolution on an integer grid capped at the round win cap. Means are cross-checked against the marginal (linearity-of-expectation) method that uses the game engine evaluator.

- There is no regulatory or industry-standard volatility scale; the thresholds above are a documented convention of this project.
- A single number cannot describe a skewed payout distribution: two games with the same standard deviation can differ greatly in hit frequency and in how much of the RTP comes from rare large wins. - Session RTP spreads use sd/sqrt(n) (central limit theorem). For short sessions the heavy right tail makes the normal approximation optimistic about downside and pessimistic about rare upside.
- A large maximum win alone does not make a game volatile; its probability matters.

Win cap: 5,000x total bet per round. P(round reaches the cap) is below the numerical floor (< 1.0e-13). The largest single free-spin win is 615x, so the cap can only be reached by several near-maximal free spins in one feature.

**Why millions of simulated spins are not enough for rare events.** The relative standard error of an estimated probability p from n independent rounds is about sqrt((1 - p) / (n p)). An event with p = 1e-6 is expected about 10 times in 10 million rounds, giving a relative error of roughly 30%; for p below 1e-8 a 10-million-round simulation will usually observe no event at all. Rare-event probabilities in this report therefore come from exact enumeration; the simulations only confirm the frequent quantities.

## 12. Reproducing these results

```bash
npm ci
npm run analyze          # exact analysis -> reports/analysis.json (+ CSV tables)
npm run simulate:100k    # seeded presets -> reports/simulation-*.json/.csv
npm run simulate:1m
npm run simulate:10m
npm run report           # regenerates this file and reports/comparison-*.csv
```

Seeded simulations are bit-for-bit reproducible for a given seed, chunk size and configuration, independent of the number of worker threads. Use `--crypto` for a non-reproducible run with the cryptographic RNG.

## 13. Limitations

- Results describe the configuration with the hash above only. Any change to the configuration invalidates them (the test suite enforces this).
- The exact analysis relies on floating-point arithmetic; probabilities below the stated numerical floor are not resolved.
- Simulation confidence intervals use the normal approximation for round returns; for heavy-tailed returns and short runs they are approximate.
- The prototype RNG and outcome generation run on the client. Real-money operation would require a server-side, independently certified RNG and outcome service (see docs/REGULATORY_READINESS.md).
